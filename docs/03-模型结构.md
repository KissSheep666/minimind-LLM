## 一、先看全貌

整个模型是一棵很浅的树:

```
MiniMindForCausalLM          (239)  ← 最外层,负责 loss 和生成
├── MiniMindModel            (201)  ← 躯干
│   ├── embed_tokens                 ← 词嵌入,把 token id 变成向量
│   ├── layers[0..7]         (183)  ← 8 个相同的 Block
│   │   ├── input_layernorm          ← RMSNorm
│   │   ├── self_attn        (91)    ← 注意力
│   │   ├── post_attention_layernorm ← RMSNorm
│   │   └── mlp              (136)   ← 前馈网络
│   └── norm                         ← 输出前的最后一次 RMSNorm
└── lm_head                          ← 把向量映射回词表大小
```

调用链:

```
MiniMindForCausalLM.forward
  └─ MiniMindModel.forward
       └─ for layer in 8 个 Block:
            └─ MiniMindBlock.forward
                 ├─ Attention.forward
                 └─ FeedForward.forward
```

**8 层、每层两个子模块、每层两条残差**——就这么简单。

| `num_hidden_layers` | 8 | Block 层数 |
| `num_attention_heads` | 8 | Query 头数 |

> 注意 `head_dim=96` 而不是 768/8=96 —— 正好相等。但 Qwen3 系列有时会让 `head_dim` 独立于 `hidden_size` 设置,所以代码里显式读取而不是现算。

### 64M 是怎么来的

| 组件 | 计算 | 参数量 |
|---|---|---|
| 每层 Attention | q:768×768 + k:768×384 + v:768×384 + o:768×768 + 两个 norm | ≈ 1.77M |
| 每层 FFN | gate + up + down = 3 × 768 × 2432 | ≈ 5.60M |
| 每层合计 | | ≈ 7.37M |
| 8 层 | 7.37M × 8 | ≈ 58.98M |
| 词嵌入 | 6400 × 768(与 lm_head 共享,只算一次) | ≈ 4.92M |
| **总计** | | **≈ 63.9M** |

这就是"64M"的来源。**自己动手算一遍,比看十篇介绍都管用。**

## 三、逐模块拆解

### 1. RMSNorm(第 50 行,11 行代码)

```python
class RMSNorm(torch.nn.Module):
    def norm(self, x):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
    def forward(self, x):
        return (self.weight * self.norm(x.float())).type_as(x)
```

**它做的事**:把每个 token 的 768 维向量按自身的"均方根"缩放,再乘一个可学习的权重。

和 LayerNorm 的区别:**不减均值**,只除以均方根。少一次减法,快一点,效果在现代 LLM 里够用。

两个细节值得注意:

- `x.float()`:计算时强制转 float32,算完再 `type_as(x)` 转回去。**这是数值稳定性的常见技巧**,半精度下 `x.pow(2).mean()` 容易溢出/下溢。
- `torch.rsqrt` = 1 / sqrt。

**形状**:进来 `[B, L, 768]`,出去 `[B, L, 768]`,逐元素操作,形状不变。

### 2. RoPE 旋转位置编码(第 62、80 行)

这是全文件最反直觉的部分,值得慢慢看。

```python
def precompute_freqs_cis(dim, end=32768, rope_base=1e6, ...):
    ...
    freqs_cos = torch.cat([torch.cos(freqs), torch.cos(freqs)], dim=-1)
    freqs_sin = torch.cat([torch.sin(freqs), torch.sin(freqs)], dim=-1)
    return freqs_cos, freqs_sin
```

```python
def apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=1):
    def rotate_half(x):
        return torch.cat((-x[..., x.shape[-1]//2:], x[..., :x.shape[-1]//2]), dim=-1)
    q_embed = q * cos + rotate_half(q) * sin
    k_embed = k * cos + rotate_half(k) * sin
    return q_embed, k_embed
```

**直觉理解(不追求严格数学)**:

Transformer 本身不知道词的顺序,要额外注入"位置"。RoPE 的做法是:**根据 token 的位置,把 Q 和 K 的向量按某个角度旋转**。

- 位置越靠后,旋转角度越大。
- 两个 token 的注意力分数只取决于它们**旋转角度的差**,也就是**相对位置**。

`precompute_freqs_cis` 做的事情就是:预先算好每个位置该用的 cos/sin 表,存起来。这样训练和推理时直接查表,不用重算。

**为什么要预计算?** 因为这张表只和位置有关,和输入无关。存一次,整个训练复用。

`rope_theta=1e6` 是一个很大的基数,配合 YaRN 可以外推到更长文本(见第 64-73 行)。

### 3. `repeat_kv`:GQA 的关键(第 86 行)

```python
def repeat_kv(x, n_rep):
    bs, slen, num_key_value_heads, head_dim = x.shape
    if n_rep == 1: return x
    return x[:, :, :, None, :].expand(bs, slen, num_key_value_heads, n_rep, head_dim) \
            .reshape(bs, slen, num_key_value_heads * n_rep, head_dim)
```

**背景**:标准多头注意力里 Q、K、V 的头数相同。GQA(Grouped Query Attention)让 **Q 有 8 个头,K/V 只有 4 个**,每 2 个 Q 头共享一组 K/V。

**好处**:

- KV cache 体积减半(推理时省内存)。
- 注意力计算量减少。

**代价**:表达能力略降,但实测几乎无损。现代 LLM(Qwen、Llama 3 等)普遍用 GQA。

`repeat_kv` 就是把 4 个 KV 头**复制**成 8 个,好和 8 个 Q 头一一配对。`n_rep = 8 // 4 = 2`。

### 4. Attention(第 91 行,44 行代码)

这是整个模型的心脏。按数据流看:

```python
# 1. 投影:把 768 维拆成头
xq, xk, xv = self.q_proj(x), self.k_proj(x), self.v_proj(x)
xq = xq.view(bsz, seq_len, 8, 96)     # [B, L, 8, 96]
xk = xk.view(bsz, seq_len, 4, 96)     # [B, L, 4, 96]
xv = xv.view(bsz, seq_len, 4, 96)     # [B, L, 4, 96]

# 2. 每个头上做 RMSNorm(Qwen3 的 QK-Norm)
xq, xk = self.q_norm(xq), self.k_norm(xk)

# 3. 加位置信息
xq, xk = apply_rotary_pos_emb(xq, xk, cos, sin)

# 4. KV cache:把历史拼进来
if past_key_value is not None:
    xk = torch.cat([past_key_value[0], xk], dim=1)
    xv = torch.cat([past_key_value[1], xv], dim=1)

# 5. 复制 KV 头,转成 [B, heads, L, 96]
xq, xk, xv = xq.transpose(1,2), repeat_kv(xk, 2).transpose(1,2), repeat_kv(xv, 2).transpose(1,2)

# 6. 算注意力
output = F.scaled_dot_product_attention(xq, xk, xv, is_causal=True)

# 7. 拼回 768 维并投影
output = output.transpose(1,2).reshape(bsz, seq_len, -1)
output = self.o_proj(output)
```

**三个要点**:

1. **`is_causal=True`**:每个位置只能看到自己和左边,不能偷看右边。这是语言模型能"预测下一个词"的前提。第 125 行的判断分支处理了不能直接用 flash 的情况(比如推理时带 cache、或需要 padding mask),那时的实现见第 128-131 行——把未来的位置填 `-inf`,softmax 后权重变 0。

2. **KV cache**(第 120-123 行):推理时,前面 token 的 K/V 不会变,存下来就不用重复算。`past_key_value` 就是一个元组 `(k_cache, v_cache)`,形状 `[B, 4, 已生成长度, 96]`。**这是让逐词生成从 O(n²) 降到 O(n) 的关键。**

3. **`q_norm` / `k_norm`**(第 104-105 行):Qwen3 引入的技巧,对每个头单独做 RMSNorm,防止注意力 logits 爆炸。小模型上尤其有用。

### 5. FeedForward:SwiGLU(第 136 行)

```python
def forward(self, x):
    return self.down_proj(self.act_fn(self.gate_proj(x)) * self.up_proj(x))
```

三个线性层:

- `gate_proj`:768 → 2432
- `up_proj`:768 → 2432
- `down_proj`:2432 → 768

计算:先分别升维,**一路过激活函数 SiLU,然后两路逐元素相乘**,最后降维。

这就是 **SwiGLU**。比传统的"升维 → ReLU → 降维"多一条门控路径,效果更好,是 Llama/Qwen 系列的标配。

**形状**:`[B, L, 768]` → `[B, L, 2432]` → `[B, L, 768]`。

> FFN 占了每层约 76% 的参数(5.6M / 7.4M)。你算一下就明白,大模型的参数大头通常在 FFN 而不是注意力。

### 6. MOEFeedForward(第 148 行)

只在 `use_moe=True` 时启用。Dense 模型可以跳过。

核心逻辑:

```python
scores = softmax(gate(x))                      # 每个专家对每个 token 的打分
topk_weight, topk_idx = topk(scores, k=1)      # 选 1 个专家
for i, expert in enumerate(self.experts):      # 只算被选中的专家
    mask = (topk_idx == i)
    ...
```

**MoE 的思想**:把一个大 FFN 拆成 4 个独立的小 FFN(专家),每个 token 只走其中 1 个。这样**总参数变大、但每个 token 的计算量不变**。

`aux_loss`(第 176-180 行)是**负载均衡损失**:如果所有 token 都涌向同一个专家,训练会不均衡,所以额外惩罚这种分布。

> 项目 README 明确说:MoE 在原生 PyTorch 下训练**比 Dense 慢约 50%**,因为专家分桶会带来大量 kernel 启停开销。这和"MoE 推理更快"不矛盾——推理和训练是两回事。

### 7. MiniMindBlock(第 183 行)

```python
def forward(self, hidden_states, position_embeddings, past_key_value=None, ...):
    residual = hidden_states
    hidden_states, present_key_value = self.self_attn(
        self.input_layernorm(hidden_states), ...
    )
    hidden_states += residual                                  # 残差 1
    hidden_states = hidden_states + self.mlp(self.post_attention_layernorm(hidden_states))  # 残差 2
    return hidden_states, present_key_value
```

**一个 Block = 两次"归一化 → 子层 → 加回原值"**。

注意是 **Pre-Norm**(先归一化再进子层),这是现代 LLM 的标准做法,比 Post-Norm 更容易训练深层网络。

**残差连接为什么重要**:它给梯度提供了一条"高速公路",让 8 层(甚至 80 层)的网络能正常反向传播。

三件事:嵌入、循环跑 8 层、最后归一化。

`register_buffer`(第 211-212 行)把 RoPE 表注册为 buffer:**会跟着模型存到显存/设备上,但不会被优化器更新**,也不出现在 `state_dict` 的持久部分(`persistent=False`)。

### 9. MiniMindForCausalLM(第 239 行)

```python
def __init__(self, config):
    self.model = MiniMindModel(config)
    self.lm_head = nn.Linear(768, 6400, bias=False)
    if self.config.tie_word_embeddings:
        self.model.embed_tokens.weight = self.lm_head.weight
```

**权重共享**:输入嵌入矩阵(6400×768)和输出层矩阵(768×6400)是同一个张量的两种用法。这省了 4.9M 参数,也让"输入词向量"和"输出词向量"在同一个空间里。

**loss 计算**(第 255-257 行):

```python
x, y = logits[..., :-1, :].contiguous(), labels[..., 1:].contiguous()
loss = F.cross_entropy(x.view(-1, x.size(-1)), y.view(-1), ignore_index=-100)
```

这一行是**整个语言模型的本质**:

- `logits[..., :-1, :]`:第 1 到倒数第 2 个位置的预测
- `labels[..., 1:]`:第 2 到最后一个位置的答案
- **错开一位** → "用前 n 个词预测第 n+1 个词"

`ignore_index=-100`:label 是 -100 的位置不计算 loss(用于 padding 和 SFT 的掩码)。

### 10. `generate`:自回归生成(第 262 行)

这是重写的生成循环,关键步骤:

```python
for _ in range(max_new_tokens):
    outputs = self.forward(input_ids[:, past_len:], past_key_values, use_cache=True)
    logits = outputs.logits[:, -1, :] / temperature   # 取最后一个位置的预测
    if top_k > 0: ...                                  # top-k 截断
    if top_p < 1.0: ...                                # top-p 核采样
    next_token = torch.multinomial(softmax(logits))    # 按概率抽样
    input_ids = torch.cat([input_ids, next_token], dim=-1)
    past_key_values = outputs.past_key_values          # 缓存更新
```

**每一轮只把新 token 送进模型**(靠 `past_len` 切片),历史信息全在 KV cache 里。这就是为什么生成长文本不会越来越慢到无法忍受。

采样参数:

| 参数 | 作用 |
|---|---|
| `temperature` | 越大越随机,越小越确定 |
| `top_k` | 只从概率最高的 k 个里选 |
| `top_p` | 只从累计概率达到 p 的最小集合里选 |
| `repetition_penalty` | 惩罚已经出现过的词,抑制复读 |

## 四、张量形状全程表

以 batch=1、序列长度 L 为例:

| 位置 | 形状 |
|---|---|
| `input_ids` | `[1, L]` |
| `embed_tokens(input_ids)` | `[1, L, 768]` |
| `q_proj(x).view(...)` | `[1, L, 8, 96]` |
| `k_proj(x).view(...)` | `[1, L, 4, 96]` |

| 转置后 q/k/v | `[1, 8, L, 96]` |
| 注意力分数 | `[1, 8, L, L]` |
| 注意力输出 | `[1, 8, L, 96]` → `[1, L, 768]` |

| FFN 输出 | `[1, L, 768]` |
| `lm_head` 输出 | `[1, L, 6400]` |

**把这张表抄下来,对照代码走一遍。形状全部对上的那一刻,Transformer 就不再神秘了。**
