# 05 · 踩坑速查

> 按"遇到什么问题 → 查哪一类"组织。所有结论均在本机(Windows 11 + Git Bash + i5-1240P + 无独显)实测或从源码确认。

---

## 一、环境类

### 1. `pip install` 一直超时

**原因**:`pypi.org` 在本机直连超时。

**解决**:显式指定清华源。

```bash
pip install <包名> -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**不要用项目 README 推荐的阿里云源** —— 本机实测 `mirrors.aliyun.com` 同样超时。

---

### 2. `numpy` 版本冲突 / 装完 import 报错

**原因**:全局 numpy 是 2.5.3,项目锁定 1.26.4。

**解决**:必须在虚拟环境里操作。

```bash
python -m venv .venv
source .venv/Scripts/activate
pip install numpy==1.26.4 -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**判断是否激活成功**:命令行前缀应出现 `(.venv)`。

---

### 3. `pip install -r requirements.txt` 失败

**原因**:全量依赖包含 `trl`、`wandb`、`swanlab`、`streamlit`、`datasets`、`sentence_transformers` 等,首轮推理完全用不到,且在 Python 3.12 上更容易冲突。

**解决**:**不要装全量**。按阶段安装:

| 做什么 | 需要什么 |
|---|---|
| 推理 | `torch` + `transformers==4.57.6` + `numpy==1.26.4` |
| 下载模型 | `modelscope`(或代理 + `huggingface_hub`) |
| LoRA | 再加 `datasets` |
| RL | 再加 `trl` 相关的依赖,按报错逐个补 |

---

### 4. Python 3.12 兼容性

项目标称 Python 3.10.16,本机是 3.12.10。

`torch` 和 `transformers==4.57.6` 在 3.12 上实测可用。**若遇到无法解决的兼容问题**,退路是装一个 Python 3.10 独立环境:

```bash
# 用 Conda(需要先装 Miniconda)
conda create -n minimind python=3.10
conda activate minimind
```

## 二、网络与代理类

### 5. HuggingFace 连不上

**原因**:直连被阻断。

**解决**:项目已确认系统代理为 `127.0.0.1:7890`,走代理后 HTTP 200 可达。

```bash
export https_proxy=http://127.0.0.1:7890
export http_proxy=http://127.0.0.1:7890
```

**一个容易误解的点**:

> Windows 系统代理开着 ≠ 命令行工具会用它。
> **Git Bash 里的 `git` 和 `curl` 不读 Windows 注册表**,必须显式 `export`。
> 而 Python 的 `requests` / `huggingface_hub` 在 Windows 上会自动读系统代理,通常不用管。

### 6. `raw.githubusercontent.com` 解析失败

**现象**:

```
curl: (6) Could not resolve host
```

**原因**:DNS 层面的干扰。

**解决**:走代理。

### 7. ModelScope 下载中断

**解决**:重新执行同一条命令,通常会续传。

```bash
modelscope download --model gongjy/minimind-3 --local_dir ./minimind-3
```

## 三、运行类

### 8. `RuntimeError: "... not implemented for 'Half'"`

**位置**:`eval_llm.py:30`

```python
return model.half().eval().to(args.device), tokenizer
```

**原因**:`half()` 强制转 float16,而 CPU 上大量算子不支持 Half。

**解决**:本仓库已改为:

```python
dtype = torch.float32 if str(args.device).startswith('cpu') else torch.half
return model.to(dtype).eval().to(args.device), tokenizer
```

**如果你重新从上游拉了代码,记得手动改这一行。**

---

### 9. `KeyError: 'qwen3'`

**原因**:`transformers` 版本太低,不认识 Qwen3 架构。

**解决**:

```bash
pip install transformers==4.57.6 -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**背景**:minimind-3 导出的 `config.json` 里写的是 `"model_type": "qwen3"`,它借用了 transformers 原生的 Qwen3 实现来加载。

---

### 10. `No module named 'transformers'` / `'torch'`

**原因**:虚拟环境没激活,或装在了别的解释器里。

**解决**:

```bash
source .venv/Scripts/activate
python -c "import torch, transformers; print(torch.__version__, transformers.__version__)"
```

---

### 10.1 补充:`OSError: [WinError 1114] ... c10.dll`

**现象**:`import torch` 时报

```
OSError: [WinError 1114] 动态链接库(DLL)初始化例程失败。
Error loading "...\torch\lib\c10.dll" or one of its dependencies.
```

**可能原因**(按优先级):

1. **安装过程被中断**,torch 只装了一半(本仓库验证时遇到过这种情况)。
2. 缺少 **Microsoft Visual C++ Redistributable**。
3. 杀毒软件隔离了 `torch\lib` 下的 DLL。

**解决**:

```bash
# 1. 彻底重来
deactivate
rm -rf .venv
python -m venv .venv
source .venv/Scripts/activate
pip install torch --index-url https://download.pytorch.org/whl/cpu

# 2. 验证
python -c "import torch; print(torch.__version__)"
```

仍失败的话,安装 VC++ 运行库(微软官方):
<https://aka.ms/vs/17/release/vc_redist.x64.exe>

> **不要**从第三方源装 torch。CPU 版必须用 `download.pytorch.org/whl/cpu`,否则可能拿到 CUDA 版或架构不匹配的轮子。

### 11. 输出全是英文 / 语法错乱

**这不是 bug。** 64M 模型的英文能力本来就这样。项目 README 里贴出的 Zero 模型英文样例本身就是崩坏的:

```
🤖️: 您提到的"Introok's the believeations of theument." 这个名字来源于中国古代的...
```

---

### 12. 虚构事实(长江源头、大熊猫吃什么……)

**这不是 bug,是 64M 参数的能力上限。**

项目自己的评测结论:

> "B 模型:表达最流畅、代码正确、结构感最好,但知识幻觉严重(长江=珠峰、大熊猫吃海产品)。"

**你用它学流程,不要用它查事实。**

---

### 13. 生成长文本越来越慢

**正常现象**。虽然有 KV cache,但每轮仍要过一次完整的前向。把 `--max_new_tokens` 调小即可:

```bash
python eval_llm.py --load_from ./minimind-3 --device cpu --max_new_tokens 256
```

## 四、训练类

### 15. 训练数据路径报错

`train_pretrain.py` 默认 `--data_path ../dataset/pretrain_t2t_mini.jsonl`,是**相对脚本所在目录**的路径。实际运行时项目通常要求从 `trainer/` 目录进入:

```bash
cd trainer
python train_pretrain.py
```

或者显式传绝对路径:

```bash
python trainer/train_pretrain.py --data_path ./dataset/pretrain_t2t_mini.jsonl
```

---

### 16. `max_seq_len` 该设多少

- 它是 **token 数**,不是字符数。
- 中文约 1.5~1.7 字符/token,英文 4~5 字符/token。
- `pretrain_t2t_mini` 推荐 `≈768`,`sft_t2t_mini` 推荐 `≈768`。
- 主线版 `pretrain_t2t` 推荐 `≈380`。
- 太大浪费算力(padding),太小截断语义。

---

### 17. 训练 loss 不降 / 变成 NaN

常见原因,按可能性排序:

1. 学习率太大(默认 5e-4,小模型上可以再降)
2. 数据读错了(检查 `data_path` 和 jsonl 字段)
3. 精度问题(CPU 上确保没有走 fp16)
4. 梯度爆炸(检查 `grad_clip`)
5. tokenizer 和模型不匹配(用了别的模型的词表)

---

### 18. 想用 CPU 训练

```bash
python trainer/train_pretrain.py --device cpu
```

脚本会自动把混合精度关掉(`train_pretrain.py:114`)。**能跑,但很慢**,只建议用来验证流程,不建议跑完整 epoch。

---

### 19. LoRA 在 CPU 上能跑吗

**能**。项目 README 明确说 `train_lora.py` 在 CPU 上通常也能比较轻快地完成。这是本地动手实验的最佳切入点。

## 五、概念类

### 20. "From Scratch" 到底指什么

| 是 | 不是 |
|---|---|
| 架构从 0 写 | 知识从 0 |
| 训练算法从 0 写 | 数据从 0 采集 |
| Tokenizer 从 0 训练 | 效果从 0 涌现 |

训练数据大量来自蒸馏。Apache 2.0 只覆盖**代码**。

---

### 21. 为什么 MoE 训练反而更慢

项目 README 原话:

> "Experts 继续增加后,实际耗时往往比同尺寸规模的 dense 模型高非常多……token 先按专家分桶、再分别做 forward,原生训练时带来的 kernel 启停和调度开销会急剧变重。"

在当前实现下,**4 专家 top-1 大约比 Dense 慢 50%**。

> 这和"MoE 推理更快"不矛盾:推理和训练是两回事,而且推理快也需要算子优化。

---

### 22. 为什么 RL 之后模型反而更会编

**对齐税**。项目自己的结论:

> "后训练往往能把某一条能力线拉得很高,但几乎都会伴随比较明显的'对齐税'。模型在特定奖励目标上变强的同时,通常会牺牲掉一部分通用性、事实性或者自然分布下的稳定性。"

**优化目标变窄 ≠ 全面变强。**

---

### 23. 为什么代码里到处是 `**kwargs`

因为要兼容 `transformers` 框架的调用约定。框架会传进来一些这个模型用不上的参数,`**kwargs` 负责兜住,避免报错。**看到它,通常意味着"这些参数可以忽略"。**

## 六、调试小技巧

### 打印张量形状

在任何 `forward` 里插一行:

```python
print("shape:", x.shape, "dtype:", x.dtype)
```

跑一次推理,对照 [03 · 模型结构](03-模型结构.md) 里的形状表。**这是读懂 Transformer 最快的办法。**

### 看 token 怎么被切分

```python
from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("./minimind-3")
text = "为什么天空是蓝色的"
ids = tok(text).input_ids
print("ids:", ids)
print("pieces:", [tok.decode([i]) for i in ids])
print("还原:", tok.decode(ids))
```

### 看 loss 是不是在正常下降

- 初始 loss 应该在 `ln(6400) ≈ 8.76` 附近(词表 6400 的均匀分布)。
- 如果一开始就是 0.001,说明 labels/掩码写错了。
- 如果一直不降,参考第 17 条。
