# 02 · 快速跑通:让它在你的机器上说话

> 目标:**30 分钟内**,在本地 CPU 上跟 64M 的 MiniMind 聊上天。
> 这一步不需要你会 Python,所有命令原样复制即可。

> **验证状态说明**:本文档中的环境信息(Python/git 版本、网络可达性、pip 源、模型文件清单)均已在本机实测;源码结论(行号、配置)逐一核对过。但**完整的"装依赖 → 下模型 → 跑推理"链路尚未在本机端到端跑通**(安装过程被主动中止),首次执行时若遇到依赖问题,请对照 [05 · 踩坑速查](05-踩坑速查.md)。

## 步骤 2:建虚拟环境

```bash
python -m venv .venv
source .venv/Scripts/activate      # Git Bash
# PowerShell 用户用: .venv\Scripts\Activate.ps1
```

激活成功后命令行前面会出现 `(.venv)`。

> **为什么必须用 venv?**
> 你全局装了 `numpy 2.5.3`,而项目锁定 `numpy==1.26.4`。不隔离的话,装依赖时要么冲突、要么把全局环境搞坏。

---

## 步骤 3:装最小依赖

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install transformers==4.57.6 numpy==1.26.4 -i https://pypi.tuna.tsinghua.edu.cn/simple
```

实测:
- `download.pytorch.org` 直连可达(HTTP 200)。
- `pypi.org` 直连**超时**,必须用 `-i` 指定清华源。
- 项目 README 推荐的阿里云源在本机**也超时**,不要照抄。

### ⚠️ 不要安装完整的 requirements.txt

`requirements.txt` 里有 `trl`、`wandb`、`swanlab`、`streamlit`、`datasets`、`sentence_transformers` 等一大堆训练用的库。**首轮推理一个都不需要**,而且它们在 Python 3.12 上更容易出兼容问题。

需要时再按阶段单独装。

## 步骤 4:下载模型(128MB)

### 路线 A:ModelScope(推荐,不用代理)

```bash
pip install modelscope -i https://pypi.tuna.tsinghua.edu.cn/simple
modelscope download --model gongjy/minimind-3 --local_dir ./minimind-3
```

### 路线 B:HuggingFace(需要代理)

```bash
export https_proxy=http://127.0.0.1:7890
export http_proxy=http://127.0.0.1:7890
git clone --depth 1 https://huggingface.co/jingyaogong/minimind-3 ./minimind-3
```

> **注意**:Git Bash 里的 `git` / `curl` **不读 Windows 系统代理**,必须显式 `export`。虽然你的系统代理已经开着(`127.0.0.1:7890`),但命令行工具不会自动使用。
>
> HuggingFace 仓库里还塞了 README 用的 20 多张配图(含 6MB 的 GIF),会一起拉下来。只想要权重的话用:
> ```bash
> pip install huggingface_hub -i https://pypi.tuna.tsinghua.edu.cn/simple
> hf download jingyaogong/minimind-3 --local-dir ./minimind-3 \
>   --include "*.json" --include "*.safetensors" --include "*.jinja"
> ```

下载完成后,`./minimind-3/` 里应该至少有:

```
config.json              # 模型结构参数
model.safetensors        # 128MB 权重
tokenizer.json           # 词表
tokenizer_config.json    # 分词器配置(含 chat template)
chat_template.jinja      # 对话模板
generation_config.json
special_tokens_map.json
```

### 一个值得知道的细节

打开 `minimind-3/config.json` 会看到:

```json
{
  "architectures": ["Qwen3ForCausalLM"],
  "model_type": "qwen3",
  "hidden_size": 768,
  "num_hidden_layers": 8,
  ...
}
```

也就是说,**导出的模型把自己包装成了 Qwen3**,从而直接复用 `transformers` 原生的 Qwen3 实现来加载。这解释了为什么 `eval_llm.py` 里 `AutoModelForCausalLM.from_pretrained()` 能直接跑通,不需要 `trust_remote_code`。

## 步骤 5:CPU 精度修正(本仓库已应用)

上游 `eval_llm.py` 第 30 行是:

```python
return model.half().eval().to(args.device), tokenizer
```

`.half()` 强制把模型转成 **float16**。而 **CPU 上大量算子不支持 Half**,会直接报:

```
RuntimeError: "LayerNormKernelImpl" not implemented for 'Half'
```
(具体算子名可能不同,但都是 `not implemented for 'Half'`。)

本仓库已改为按设备选择精度:

```python
dtype = torch.float32 if str(args.device).startswith('cpu') else torch.half
return model.to(dtype).eval().to(args.device), tokenizer
```

**只影响精度,不影响逻辑。** CPU 上用 float32,显存/内存占用约 256MB,完全无压力。

> 如果你是从上游重新拉的代码,记得手动改这一行。

## 步骤 6:跑起来

```bash
python eval_llm.py --load_from ./minimind-3 --device cpu
```

会先提示:

```
[0] 自动测试
[1] 手动输入
```

输入 `1`,然后开始聊天。

**退出方式**:直接按回车(空输入)结束,或 `Ctrl+C`。

## 预期现象

### 速度

每轮回答后脚本会打印:

```
[Speed]: xx tokens/s
```

64M 模型在 i5-1240P 上做 CPU 推理,预期在**个位数到几十 tokens/s**。这个数字就是你这台机器的真实水平,记下来。

### 质量

- **中文**:通顺、格式完整、很像那么回事。
- **事实**:大量编造。问它地理、历史、科学事实,大概率答错。
- **英文**:明显崩坏,语法混乱。

这是 64M 参数的真实水位,**不是你的配置问题**。

### 验证它真的在"猜下一个词"

观察输出是**一个 token 一个 token 流式吐出来的**。这就是自回归生成的直观体现:每吐一个词,把它接回输入,再猜下一个。

## 常见报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `not implemented for 'Half'` | CPU 跑了 float16 | 应用步骤 5 的补丁 |
| `No module named 'transformers'` | venv 没激活或依赖没装 | 重新 `source .venv/Scripts/activate` |
| `Couldn't connect to huggingface.co` | 没走代理 | `export https_proxy=http://127.0.0.1:7890` |
| `pip` 安装超时 | PyPI 直连不通 | 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| `numpy` 版本冲突 | 用了全局环境 | 用 venv,不要全局安装 |
| `KeyError: 'qwen3'` | transformers 版本太低 | 必须是 `4.57.6` |
| 输出乱码/全是英文 | 正常现象 | 64M 模型的英文能力就是这样 |
